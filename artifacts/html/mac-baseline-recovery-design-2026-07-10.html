Mac baseline recovery

AI Register Explorer · codex/reimagine-site-imagegen · commit 0ddecdb

Establish a reproducible, reviewable Mac development baseline for the July production branch without changing application behaviour or touching production.

Decision

Use the July redesign branch as the baseline. Version durable project instructions, tracker pointers, and the two final July production screenshots. Preserve older migrated logs and intermediate screenshots in place while excluding them only from this checkout through .git/info/exclude.

Why this approach

ApproachAssessment
Version durable evidence; locally exclude migrated intermediatesSelected. Keeps release proof portable, avoids binary bloat, and produces a quiet local worktree without imposing broad ignore rules on future contributors.
Commit every untracked artifactRejected. It would add many redundant screenshots and machine-local logs to Git without improving reproducibility.
Leave all artifacts untrackedRejected. Persistent status noise would make later accidental edits harder to detect.

Repository changes

  • Restore owner write permission on migrated repository directories so Mac tooling can create planned files and build output. Directory permission metadata is not committed by Git.
  • Add .gitattributes with a repository-wide LF policy for text files.
  • Normalize only the three currently affected tracked files: .gitignore, next-env.d.ts, and src/components/StatsBar.tsx. No semantic code changes are intended.
  • Version the existing project AGENTS.md.
  • Convert tasks/todo.md and tasks/lessons.md from empty migration scaffolds into short pointers to the authoritative HTML trackers.
  • Version artifacts/html/README.md and the two referenced July release captures: live-imagegen-release-desktop-2026-07-08.png and live-imagegen-release-mobile-2026-07-08.png.
  • Add exact local-only exclusions for remaining migrated logs and intermediate screenshots to .git/info/exclude; do not delete or move those files.

Verification design

  1. Confirm the working diff contains only the intended policy, documentation, tracker, and release-evidence changes.
  2. Install dependencies with npm ci from the committed lockfile.
  3. Run sequentially: npm run typecheck, npm audit, npm run test:ui, npm run test:a11y, and npm run build. Sequential execution avoids the known shared .next cache conflict.
  4. Require git diff --check to pass and verify the worktree contains no unexplained files.
  5. Run autoreview --mode local; verify each finding against the actual files, fix accepted findings, and rerun affected checks plus autoreview.
  6. Create one focused local commit after all gates pass.

Explicit boundaries

  • No merge into master.
  • No push, pull request, Vercel deployment, live-site verification, or external-data mutation.
  • No product, visual, legal-copy, dependency-version, or application-behaviour changes.
  • If locked dependency installation or current Mac verification fails, diagnose and report the failure before expanding scope.

Success criteria

  • The July production branch is the explicit continuation baseline.
  • Line-ending drift is prevented and git diff --check passes.
  • Durable release evidence is versioned; local migrated evidence remains intact.
  • The full Mac verification suite has fresh passing evidence.
  • Structured review reports no accepted or actionable findings.
  • A focused local commit records the recovery; remote and production state remain unchanged.
