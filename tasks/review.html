Adversarial UI/UX Review Notes

This review treats the site as a civic data-exploration product. The bar is production trust, not visual novelty.

Product Assumptions

  • Primary users: researchers, journalists, public servants, policy analysts, civic-tech users, and technically curious members of the public.
  • Primary journey: understand the data source, search/filter the federal AI register, inspect records, and export filtered data.
  • Conversion goal: successful data exploration and source trust, not lead capture.

Fixed Findings

SeverityFindingResolution
P1Primary CTA led into charts before search/filter controls.Moved search/filter toolbar before charts and added a clear explorer heading.
P1Default collapsed department grouping hid real records from first-time users.Changed default grouping to All so rows are visible immediately.
P1Mobile filter controls were truncated and cramped at 390 px.Stacked mobile filters full-width and moved result/actions into their own row.
P2No-results state had explanation but no recovery action.Added a clear search and filters button to the empty state.
P2Hero felt too tall for a data explorer and used aggressive display tracking.Reduced hero height/type scale and normalized H1 tracking.
P2Floating scroll control overlapped mobile content and was English-only.Hidden on mobile and localized for larger screens.
P1No repeatable UI/accessibility regression gate existed.Added Playwright tests for homepage journey, mobile layout, public routes, and axe accessibility.
P1Axe found contrast, landmark, and ARIA violations.Darkened muted text tokens, added landmarks, and corrected icon semantics.
P1Homepage first-load JavaScript was too heavy for a public data explorer.Dynamically loaded charts; build output dropped from about 250 kB to 130 kB first-load JS.
P2Source/freshness context was not visible in the active exploration workflow.Added source, updated date, and cache-window copy beside the controls.
P1Dependency audit reported Next/PostCSS vulnerabilities.Updated Next resolution and overrode PostCSS to patched 8.5.15; audit now reports zero vulnerabilities.
P1Charts lacked a visible data alternative and one status-axis label clipped at smaller desktop widths.Added chart-data toggles with visible tables and corrected status chart axis spacing.
P1Mobile browsing still relied on dense desktop table behaviour.Added mobile-native result cards with scannable metadata and full-width detail actions.
P1Keyboard, CSV export, dark mode, and API failure states were not regression-tested.Extended Playwright coverage for Ctrl/Cmd+K, detail dialog keyboard flow, CSV download, dark-mode axe, and failed API copy.
P1Returning French users could still see English server-rendered legal content before hydration.Added a server-readable language cookie, passed initial language through the layout/provider, and verified French privacy rendering with JavaScript disabled.
P1Upstream CKAN failure produced a dead-end explorer state.Added bounded upstream retry/timeout plus a user-facing retry button and official source link.
P2Search did not normalize accents and binary filters exposed raw Y/N codes.Added accent-insensitive search across more bilingual fields and changed binary filter options to readable labels.
P2High-parallel Playwright runs could leave lazy chart assertions waiting on the dev server.Capped Playwright workers at 4 locally and 2 in CI to reduce dev-server contention while keeping the suite parallel.

Remaining Review Risks

SeverityRiskRecommended next action
P1Production deployment state was not changed in this pass.Deploy only after explicit approval, then verify live routes and screenshots.
P2Chart tables are now visible, but chart exports and richer comparison summaries are still absent.Add per-chart copy/export only if users actually need chart-level reuse beyond the full CSV export.
P2Automated tests cover the main journeys, French initial render, retry, accent search, and binary filters, but not every possible multi-filter combination.Add exhaustive multi-filter tests only if filter logic grows more complex or gets backed by server-side query parameters.
P3Some secondary pages are content-heavy and could be more scannable.Add summary boxes or stronger section hierarchy after product/legal review.
